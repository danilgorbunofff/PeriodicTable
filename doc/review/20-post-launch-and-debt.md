## 1. Scope

This is the file the batches 6+ do not write. Everything the product decided to live without — with the condition that makes it due — is registered here, once, so the decision survives the session that made it. The neighbours own the fixes; this owns the calendar.

In scope: the advisory acceptance and its tripwire; the Turnstile CSP premise corrected against the served header; the unused `WHOP_*` vars and the retained `PaymentProvider` enum values; the `Payment` table's twelve rows in five shapes, including the six dead `PENDING` rows and the three stake-less `PAID` rows; the absence of error tracking; the reconcile/tick alerting path and its cadence; the unconfigured rate-limit store; the support, moderation, refund-dispute and retention-backup cadences; growth experiments; the v2 backlog gate; and the two questions nothing has answered — whether the game ever ends, and what happens to holders' money if the site is shut down.

Out of scope, and owned by the docs that will fix them: the runbook and operator-tooling set (17, `00-REVIEW-PLAN.md:144`), monitoring design and error tracking as a *build* (18, `:147`), PII retention and the restore drill as a *procedure* (12, `:127`), the money path itself (06/07/08, `:219-221`), legal copy as a *document* (16, `:229`), and the launch-day gate itself (`19` §8). This doc only says when each deferral comes due and who owns it when it does.

**This doc is read-only.** Nothing here deletes rows, sets variables, schedules jobs, revokes keys or writes legal text. §8 says how the register is kept; §9 is the operator's decision list; the operator performs and §11 records.

## 3. Intended behaviour

Four artefacts already make promises about the period this doc covers; the register exists because each promise has an edge that is currently unowned.

1. **The advisory acceptance is scoped and time-boxed.** `ops/accepted-advisories.json` accepts `next` 14.2.35 at **critical**, gives a per-advisory reachability reason, schedules "Framework migration to Next 16 + React 19 after launch", states the **tripwire** in full ("holds only while `next.config.mjs` keeps its `images` key absent … and hosting stays Linux; either changing makes both criticals live") and sets `expires: 2026-12-31`. What nothing carries is the *check*: no alarm, no CI step, no calendar entry fires when the tripwire moves (`17`, `18` territory).
2. **The money path self-checks, once per tick.** `app/api/jobs/reconcile/route.ts:8-45` states its purpose — "the sole reader for a `PAID` payment whose stored provider figure diverges" — and its channel: "A divergent row is answered as **503**, not as `ok: false` inside a 200. The status code is the only channel the external pinger can read". `HANDOFF.md:807-821` then decided the pinger **optional** because the GitHub tick "does alert". R20-7 is about the gap between those two sentences.
3. **Harm is answered within published times.** `abuse@` within 72 hours, `app/legal/[slug]/page.tsx:110`; a report button that needs no account, `:109`; `ops/takedown.md` supplies Intake (`:6`), Triage `<24h` (`:11`), Contain (`:22`), Failed deliveries (`:38`), Rollback of a bad moderation (`:44`) and Comms (`:48`). The playbook covers *a listing*. It has no section for the site itself being unavailable, wound down, or handed over — which is where R20-15 lives.
4. **Nothing gets built ahead of its trigger.** `doc/phase-6-v2/README.md:6` — "start a V2 item only when its trigger metric hits AND MVP funnel is stable for 2 weeks"; `:12` — "Global non-goals for V2 (still no): timers/expiry, fractional tile ownership, on-chain settlement (revisit at $50k pool)". The rule is sound and unread: the funnel half of it depends on analytics that do not currently serve (`19` §7 R19-1).

## 7. Findings

Fifteen rows. The first seven are the debt the plan named for this phase; the rest are the longer horizon. Every row carries **Due when** and **Deferred where** — that is the acceptance criterion of this doc (`19` §8 is the launch gate; §8 here is the register's own upkeep).

### R20-1 — A `critical` dependency acceptance with a hard expiry and an alarm-free tripwire

- **Severity.** P2 · **Category.** security · **Status.** accepted-risk (reason in §9 Q6)
- **Evidence.** §5.2 — `ops/accepted-advisories.json`: `next` `14.2.35`, `critical`, both criticals assessed unreachable by reachability, four more unreachable, remaining exposure "availability only"; `expires: 2026-12-31`; the tripwire in full: the acceptance "holds only while `next.config.mjs` keeps its `images` key absent (no `remotePatterns`, no AVIF formats) and hosting stays Linux; either changing makes both criticals live, so re-assess before that lands". The reachability probes are live and dated (`checklist:314`, `/_next/image` remote url → `400`, `Accept: image/avif` → `200 image/webp`), the audit's real state is `npm audit --omit=dev` → `next` critical with no 14.x fix (`checklist:314`), and the entry's own assessment date is after its commit (U20-6).
- **Deferred where.** `ops/accepted-advisories.json` (`scheduled`: "Framework migration to Next 16 + React 19 after launch; payments went live 2026-09-14, so this is post-launch debt rather than a pre-launch gate"); `doc/PROD-READINESS-CHECKLIST.md:314` ("The Next 16 migration is now recorded as post-launch debt").
- **Due when.** (a) **Event, no date:** the moment `next.config.mjs` gains an `images` key or the host stops being Vercel Linux — re-assess before the change lands, not after; (b) **Date:** `2026-12-31` — re-argue the acceptance against fresh probes, or run the migration; (c) **Threshold:** the first `app/api/**` path that adds a Server Action, a `middleware.ts`, or a rewrite, because those are what currently make the other four advisories unreachable.
- **Proposed fix.** Cheap half now: add a CI or `ops/` check that greps `next.config.mjs` for an `images` key and fails the build, so the tripwire cannot be crossed silently — the acceptance is only as good as the check. Expensive half at the due-date: the Next 16 + React 19 migration on its own branch, with the two probes from `checklist:314` re-run on a preview deploy before it ships.

### R20-2 — The plan's "dead Turnstile CSP entries" premise is wrong: both entries are load-bearing

- **Severity.** P3 · **Category.** security · **Status.** wontfix — the entries stay (reason in §9)
- **Evidence.** §5.6 — `00-REVIEW-PLAN.md:155` lists "dead Turnstile CSP entries"; the served header on 2026-09-15T08:16:27Z carries `https://challenges.cloudflare.com` in both `script-src` and `frame-src`; `components/TurnstileWidget.tsx:22` loads `api.js?render=explicit` from that origin; `TURNSTILE_SECRET` is a **required** production variable (`lib/env.ts:44,76`) and checkout verifies Turnstile unconditionally (`checklist:309`, citing `app/api/checkout/route.ts:132`, which `403`s the dev-pay escape hatch whenever Stripe is configured).
